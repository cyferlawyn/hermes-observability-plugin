## Synthetic performance measurements

These are diagnostic measurements from a single local run on **2026-10-15**. The synthetic hook run uses the actual `runtime.profile_connection` implementation and a temporary SQLite WAL profile. With no explicit `database.synchronous` preference, the plugin's thread-local WAL connection uses `synchronous=NORMAL`; explicit Hermes settings are honored, and the read-model fixture connection uses SQLite's default `synchronous=FULL`. The plugin-local NORMAL setting reduces per-hook sync cost but can lose the latest telemetry commits after sudden power failure; it leaves Hermes' core data connection untouched.

Environment: AMD Embedded G-Series GX-420GI Radeon R7E, 4 logical CPUs, Linux 6.1.0-53-amd64, Python 3.11.2, SQLite 3.40.1, Node v26.8.1. The hook connection reports `journal_mode=wal`, `synchronous=1` (`NORMAL`); the read-model fixture connection reports `journal_mode=wal`, `synchronous=2` (`FULL`).

Dataset: 80 sessions, 2,303 tool-call rows, 133 provider attempts; the Desktop render harness used 25 tool identities, 20 findings, and 96 selected-session events. The scripts warm up before timing and report nearest-rank p50/p95.

| Operation | p50 | p95 | Samples |
|---|---:|---:|---:|
| Ten synthetic no-op tool slots, observer disabled | 0.0016 ms | 0.0020 ms | 200 |
| Ten synthetic tool-call start/completion pairs, observer enabled | 9.6245 ms | 36.2330 ms | 200 |
| Profile overview query/aggregation | 58.6431 ms | 78.0303 ms | 60 |
| Selected-session trace query/assembly | 1.1332 ms | 1.5042 ms | 60 |
| Control room element construction + tree traversal | 7.262 ms | 9.960 ms | 60 |
| Failure queue element construction + tree traversal | 2.412 ms | 3.306 ms | 60 |
| Trace ledger element construction + tree traversal | 2.797 ms | 3.551 ms | 60 |

The observer comparison excludes model/provider generation and actual tool execution. The JavaScript harness measures React-element construction and tree traversal, **not Electron DOM layout or paint**. These figures are local baselines, not an SLO or a hardware-independent guarantee; repeat them on the target gateway/storage and inspect live turn latency before making broader performance claims.

## Remaining release boundary

- The benchmark does not exercise a live model/provider turn or Electron paint.
- Results do not imply complete capture: observer hooks remain fail-open and “Observed — no known gaps” remains a best-effort coverage state.
- No task/session-success inference, fuzzy failure grouping, generated recommendations, or unattended remediation is included.
